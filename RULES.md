# Documentation Rules

## Rule 1 — Never Delete Documentation Files

The following files are permanent parts of this project.

They **must never be deleted, renamed, or replaced** unless the project owner explicitly instructs otherwise.

```
README.md
PROJECT_STATUS.md
INSTALLATION.md
FEATURES.md
DATABASE.md
API.md
ARCHITECTURE.md
DEPLOYMENT.md
TESTING.md
ROADMAP.md
SECURITY.md
CONTRIBUTING.md
CHANGELOG.md
TROUBLESHOOTING.md
CODE_OF_CONDUCT.md
LICENSE.md
RULES.md
```

---

## Rule 2 — Update Instead of Replace

Documentation should be updated by modifying only the relevant sections.

Do **NOT**:

* Delete the entire file.
* Replace the entire document unnecessarily.
* Remove useful historical information.

Instead:

* Preserve existing content whenever possible.
* Add new information.
* Correct outdated information.
* Improve clarity.

---

## Rule 3 — Keep Documentation Accurate

Documentation must always match the actual implementation.

Never mark incomplete features as completed.

Use clear status indicators such as:

* ✅ Completed
* 🟡 In Progress
* 🔵 Planned

---

## Rule 4 — Keep Files Organized

Maintain:

* Headings
* Tables
* Markdown formatting
* Existing structure
* Internal consistency

---

# Source Code Rules

## Rule 5 — Preserve Project Structure

Do not remove project directories or important files without owner approval.

Avoid unnecessary restructuring.

---

## Rule 6 — Write Clean Code

Code should be:

* Readable
* Well documented
* Modular
* Consistent
* Easy to maintain

---

## Rule 7 — Follow Existing Architecture

New features should follow the project's architecture and coding style unless the owner requests a redesign.

---

# Security Rules

## Rule 8 — Never Expose Sensitive Information

Do not commit:

* Passwords
* API keys
* Secret keys
* Database credentials
* Environment files

Use environment variables instead.

---

# Version Control Rules

## Rule 9 — Update Documentation with Code Changes

Whenever code changes significantly, update the relevant documentation.

Examples:

* New API → `API.md`
* New feature → `FEATURES.md`
* Database changes → `DATABASE.md`
* New release → `CHANGELOG.md`
* Project progress → `PROJECT_STATUS.md`

---

## Rule 10 — Preserve Project History

Do not remove:

* Previous releases
* Changelog entries
* Historical milestones
* Completed work

History should remain available for reference.

# AI Assistant Rules

When an AI assistant modifies this repository, it must:

* Preserve all documentation files.
* Never delete documentation files.
* Never rename documentation files.
* Update existing content instead of replacing entire documents.
* Maintain Markdown formatting.
* Keep documentation synchronized with the code.
* Respect the proprietary license.
* Follow the project architecture.
